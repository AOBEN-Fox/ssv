# T1/T2 最新帧显示与基于 PTS 的展示预测实施计划

## 目标与顺序

本计划实现
[T1/T2 最新帧显示与基于 PTS 的展示预测 spec](../specs/2026-07-24-T1T2-最新帧显示与PTS展示预测-spec.md)。
它是本次交付的唯一实施计划，按以下依赖顺序推进：

1. `ssv_meta` 公共元数据契约；
2. infer、track、pub 的 timing 与元数据传递迁移；
3. overlay predictor、runtime、renderer 与 GObject adapter；
4. T1 latest-frame pipeline、YAML 和插件属性接线；
5. 自动化、本机性能与真实链路验证。

实现采用纵向 TDD 小步：先在公开 seam 增加失败测试，再实现最小行为并保持每阶段可构建。
不提交、不推送、不创建 PR，除非用户另行明确要求。

## TDD seam

测试只通过以下公开边界观察行为：

- `ssv_meta(source_id)`；
- `SsvSourceMeta` 的 publish、consume、history、generation 与 stats；
- `SsvTimelineCursor`；
- `OverlayMotionPredictor`、`OverlayRuntime`、`OverlayRenderer`；
- `ssvoverlay` 的 `font-face`、`font-size` 属性与 YAML→pipeline 接线；
- GStreamer 插件属性、buffer/event 回调和 Redis payload；
- `./ssv` CLI、YAML 与最终 pipeline 字符串。

registry、mutex、slot、deque、规范化 helper 与 reset 临界区属于实现细节，不直接测试。

## 实施步骤

### 1. 冻结 ssv_meta 公共契约

- [x] 增加 `SsvFrameTiming`、detection/tracked/overlay 帧级 timing 测试。
- [x] 证明 tracking 字段只属于 `SsvTrackedObject`，帧类型使用组合而非继承。
- [x] 把 timeline 与 result-channel 测试迁移到 source handle seam，并先确认红灯。
- [x] 覆盖 move-only detection、空帧、`frame_id == 0` 和 publish 后规范化。
- [x] 覆盖 wrong source/generation、无 PTS、重复/迟到 PTS、occupied 与 empty 结果。

### 2. 实现 source-scoped ssv_meta 深模块

- [x] 使用 Pimpl 隐藏每个 source 的 mutex、generation、segment、两个 slot、history 和 stats。
- [x] generation 换代与 detection/publication/history 清理在一个 source 临界区完成。
- [x] 连续 FLUSH/SEGMENT、两个 cursor 并发观察同一 reset 时只实际换代一次。
- [x] detection 以移动语义交接，不复制 vector，不阻塞、不静默覆盖。
- [x] `publish_tracked` 继承 observation identity，只创建一次 immutable snapshot。
- [x] publication slot 与 history 原子提交同一 shared pointer，失败时都不前进。
- [x] history 实现严格递增 PTS、因果查询、空 snapshot、2 秒窗口和 64 项上限。
- [x] registry 返回稳定 source handle，并隔离多 source 与 generation。
- [x] 将 frame types、timeline 与 result channels 合并进 `ssv_meta.hpp/.cpp`，删除过渡期并列公共文件和实现耦合测试。

### 3. 迁移 infer、track 与 pub

- [x] `SsvVideoFrame` 继承输入 buffer timing；同步、异步、mock 与异常路径保持一致。
- [x] `ssvinfer` 注册 `source-id`，用 cursor 处理事件/buffer 并发布 detection。
- [x] `ssvtrack` 从同一 source handle 消费 detection，以其 timing 发布 tracked objects。
- [x] 当前 track buffer timing 与 observation 不匹配时不向 GMC 提供错误像素。
- [x] `BoTSortProcessor` 返回组合后的 tracked DTO，不修改 BoT-SORT Kalman 和生命周期。
- [x] `ssvpub` 注册相同 `source-id`，消费 snapshot 并在发送前重检 generation。
- [x] 空 snapshot 释放 publication slot，但不发送空 Redis detection 消息。
- [x] payload 测试逐字段确认 Redis schema、墙钟 `timestamp_ms` 和 source 语义不变。

### 4. 实现展示 predictor、runtime 与 renderer

- [x] 用失败测试覆盖首次观测、真实 dt、重复 predict、horizon 和 generation reset。
- [x] 覆盖权威集合缺失 ID、空 snapshot、LOST/DEAD、class 变化和无 track ID。
- [x] 覆盖 NaN/Inf、非正 extent、部分/完全越界和 clamp 不反馈状态。
- [x] 实现八维常速度 Kalman，predict 在副本上外推，不修改正式观测状态。
- [x] synthetic 5 FPS/30 FPS 匀速数据满足中心误差降低与 IoU 门槛。
- [x] `OverlayRuntime` 组合 timeline、history、predictor、renderer 和聚合 stats。
- [x] 一个 snapshot 只 observe 一次；绘制前重检 generation。
- [x] prediction disabled 使用 hold-last，但保留相同 freshness guard。
- [x] `OverlayRenderer` 复用容量，跳过不足 1 像素的框，不复制视频帧。

### 5. 收窄 GObject adapter

- [x] `_SsvOverlay` 只保存 GObject parent、标量属性、source ID 与 runtime 指针。
- [x] start/stop/finalize 显式管理 runtime，GLib 实例内不放非平凡 C++ 成员。
- [x] 注册 `source-id`、`motion-prediction`、`max-horizon-ms` 及范围/default。
- [x] transform 只负责 timing、map/unmap 与 runtime 调用；event 处理 SEGMENT/FLUSH。
- [x] GstCheck 覆盖属性、生命周期、无 PTS、reset、wrong source 与受控 buffer timing。

### 6. 实现 latest-frame pipeline 与配置

- [x] CLI 红灯断言示例 YAML、四插件同 source ID 和统一 display queue。
- [x] 严格校验 boolean、正 display FPS、`1..300` horizon 与非空显式 source ID。
- [x] 显示 queue 使用 `max-size-buffers=1 leaky=downstream`。
- [x] 显示 `videorate` 使用 `drop-only=true max-rate=<display.fps>`，不以 exact 整数 caps

## 回滚边界

- 展示策略运行时回滚只使用 `display.latest_frame: false` 或
  `display.motion_prediction.enabled: false`。
- 代码回滚不得恢复 raw detection 覆盖 tracked overlay、跨 generation 可见或重复 snapshot
  vector 复制。
- 回滚不修改分析 FPS、RTSP latency、模型、Redis schema、事件、证据或 TensorRT 支持。

## 完成定义

common 的感知结果契约只由 `ssv_meta` 定义，包含纯值类型与 source-scoped handle；infer、track、pub、overlay
使用同一 source ID 并按 generation 隔离；显示分支保持 1× latest-frame；展示预测只影响
绘制；overlay 字体 face/size 可从 YAML 配置且不增加字体运行库；示例 YAML 不参与默认运行
配置搜索；Redis 与 TensorRT 边界不变。全部适用自动化与本机性能门槛有结果，无法执行的真实
链路验证有准确外部原因记录；提交和 PR 只在用户明确授权后执行。
